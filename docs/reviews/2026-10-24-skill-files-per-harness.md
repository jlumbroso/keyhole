# How each harness finds a skill or standing instructions in a project, and the Agent Skills convention

- **Date**: 2026-10-24
- **By**: Surveyor 5.1 (Claude Fable 5.1), read not run
- **For**: Glazier's brief `2026-10-24-2240-glazier-to-surveyor-skill-files-per-harness.md`; ADR-0008, QST-SKILL-REACH
- **Sources, pinned**: agentskills.io (specification and client-implementation guide, undated, fetched 2026-10-24; the adopters list from the site's repository data file); Claude Code's documentation as of 2026-10-24 (it names 2.1.277 for `AGENTS.md`); Codex CLI at `rust-v0.163.0` and its documentation; Gemini CLI at `v0.64.0` and its documentation; Grok Build at the public commit `2bdd1d6a` and docs.x.ai; Cursor's documentation (it names Cursor 2.4); VS Code at tags 1.134.0 and 1.141.0 (`src/vs/workbench/contrib/chat/common/promptSyntax/`). Documentation lookups were delegated and the quotes are the vendors'; the VS Code lines are mine.

## TL;DR

1. **Two project files reach everything.** `.agents/skills/<name>/SKILL.md` is read by Codex, Gemini CLI, Grok Build, Cursor and VS Code's chat; `.claude/skills/<name>/SKILL.md` is read by Claude Code, and also by Cursor, Grok Build and VS Code. **Claude Code does not read `.agents/`** (its documentation says so, for instruction files, and lists no `.agents` skill location); Codex and Gemini do not read `.claude/skills/`. So Keyhole writes the same skill to both folders, and no harness is left out.
2. **One text serves both copies unchanged** if it stays inside the Agent Skills fields: `name` (lowercase, hyphens, 1–64 characters, equal to the folder name) and `description` (1–1024 characters), optionally `license`, `compatibility`, `metadata`. Every reader here accepts that shape; Claude Code ignores fields it does not know, and the standard tells other tools to do the same with Claude Code's extras, so Keyhole should use none of them.
3. **Skills load on demand everywhere**: the name and description are listed at start, the body only when the model decides the skill applies (Gemini adds a consent prompt at that moment). Standing-instruction files (`AGENTS.md`, `GEMINI.md`, `CLAUDE.md`) load whole at session start, under caps, and are the project's files, not Keyhole's to write.
4. **Trust differs.** Project skills are gated on folder trust in Gemini and Grok Build, not gated in Codex or Claude Code (Claude Code honors a project skill's `allowed-tools` even in a folder never trusted), not documented in Cursor, and not gated in VS Code. Keyhole's skill should declare no tools, so that gap costs nothing.
5. **The home folder.** `~/.agents/skills/` is read by Codex, Gemini, Grok, Cursor and VS Code; `~/.claude/skills/` by Claude Code, Grok, Cursor and VS Code. A home install, the person's separate choice as ADR-0008 says, is the same two folders at home. Note Claude Code's precedence is the reverse of the convention's: its personal skill overrides a project skill of the same name.

## 1. The Agent Skills convention

- **The format is the specification; the folders are a convention.** The specification (https://agentskills.io/specification) defines only what is inside a skill: "A skill is a directory containing, at minimum, a `SKILL.md` file" with YAML front matter; `name` "Max 64 characters. Lowercase letters, numbers, and hyphens only. Must not start or end with a hyphen" and "Must match the parent directory name"; `description` "Max 1024 characters. Non-empty. Describes what the skill does and when to use it"; optional `license`, `compatibility` (≤500 characters), `metadata` (string map), `allowed-tools` ("Experimental"). Progressive disclosure: "The `name` and `description` fields are loaded at startup for all skills"; "The full `SKILL.md` body is loaded when the skill is activated"; "Keep your main `SKILL.md` under 500 lines."
- **The folders** appear in the client-implementation guide (https://agentskills.io/client-implementation/adding-skills-support): "While the Agent Skills specification does not mandate where skill directories live (it only defines what goes inside them), scanning `.agents/skills/` means skills installed by other compliant clients are automatically visible to yours"; scopes `<project>/.agents/skills/` and `~/.agents/skills/`, beside each client's own folder; "Some implementations also scan `.claude/skills/` … for pragmatic compatibility"; precedence "project-level skills override user-level skills"; trust: "Consider gating project-level skill loading on a trust check". The quickstart says "VS Code looks for skills in `.agents/skills/` by default" and "The same skill works in any compatible agent, including Claude Code and OpenAI Codex" (for Claude Code, through `.claude/skills/`, see section 3).
- **Adopters**: the site's showcase lists 46 clients, among them Claude Code, ChatGPT & Codex, Gemini CLI, Cursor, VS Code and GitHub Copilot; it does not say per client which folders are read, which is what the rest of this review establishes.

Two details that matter for the install:

- **Precedence is not uniform.** The convention says project over user; Claude Code says the opposite ("With `deploy` in both `~/.claude/skills/` and the project's `.claude/skills/`, `/deploy` runs the personal one"); Grok deduplicates by name, higher-priority location first; Codex does not merge ("both can appear in skill selectors"). For Keyhole this means a home copy and a project copy must say the same thing, or the person sees whichever their harness prefers.
- **Two folders, one skill, two listings.** Cursor, Grok and VS Code read both `.agents/skills/` and `.claude/skills/`; Grok deduplicates by name, Cursor and VS Code are not documented to. A person using those may see "keyhole" twice. A symbolic link from one folder to the other would avoid it, and Codex follows symlinks, but Claude Code's behavior on a linked skill folder is not documented and Windows links need privileges; two real copies with the same checksum line (ADR-0008's plan) are the safer shape, and a duplicate listing is harmless.

## 3. Claude Code, for comparison, with the two facts that decide the route

- Skills live at `.claude/skills/<name>/SKILL.md` (project, and in every parent up to the repository root), `~/.claude/skills/`, plugins and the managed directory; "Claude Code skills follow the Agent Skills open standard" and extend it (`when_to_use`, `disable-model-invocation`, `context`, `agent`, hooks, …). Outside Claude Code those extra fields are "a hard error" in some readers (claude.ai's API), so a cross-harness skill uses only the standard's fields.
- **`.agents/` is not read**: "Not read: `AGENTS.local.md`, `AGENTS.override.md`, or anything under a `.agents/` directory" (memory page), and the skills page lists no such location. Hence the second copy.
- `AGENTS.md` is read since 2.1.277, but only when no `CLAUDE.md` or `CLAUDE.local.md` exists in the working directory or above, unless the person sets `instructionFiles` to `claude-md-and-agents-md`. A project with a `CLAUDE.md`, as both of ours have, never shows Claude Code its `AGENTS.md`.
- Project skills are not trust-gated, and neither are their `allowed-tools`; Keyhole's skill declares none.

## 4. One file, several harnesses

| File | Read whole at start by | Read on demand (skill) by |
| --- | --- | --- |
| `AGENTS.md` | Codex (trusted), Grok (trusted), Cursor, Claude Code (only without `CLAUDE.md`), Gemini (opt-in) | — |
| `CLAUDE.md` | Claude Code, Grok (compat), Cursor | — |
| `GEMINI.md` | Gemini | — |
| `.agents/skills/<name>/SKILL.md` | — | Codex, Gemini (trusted), Grok (trusted), Cursor, VS Code |
| `.claude/skills/<name>/SKILL.md` | — | Claude Code, Grok (trusted), Cursor, VS Code |

`AGENTS.md` is the widest standing-instruction file, but it is the project's own file, read whole into every session, capped at 32 KiB by Codex, and invisible to Claude Code wherever a `CLAUDE.md` exists. A skill, listed by a one-line description and loaded when a secret is in play, is the right vehicle for "never take a secret in the conversation", and two copies of it reach all six readers. If the project wants a standing one-liner too ("Secrets go through Keyhole; see the `keyhole` skill"), that is a sentence the person adds to their `AGENTS.md` or `CLAUDE.md`, which the installer can offer to copy, not write.

## 5. What this does not settle

- Whether Cursor and VS Code list the same skill twice when both folders hold it, and how each orders duplicates; a hand check with both copies in place.
- Gemini's trusted-folders documentation says the feature is off by default while the code at `v0.64.0` defaults it on (`isFolderTrustEnabled` is `?? true`), the same discrepancy noted in the harness review's corrections; the manual should describe the code's behavior.
- Whether Claude Code reads a symbolic link in `.claude/skills/`; not documented, and not needed if two copies are written.
