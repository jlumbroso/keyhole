Keyhole's first release is being prepared. It is not yet available from the extension registries. The walkthrough in this manual applies once Keyhole is installed.

Your project may need an API key, token, password, or database connection string to use another service. Keyhole lets you paste that value into a masked box in VS Code and save it in the project's .env file.

Your assistant can explain which setting the project needs and where to obtain it. You do not need to paste the secret into the conversation.

Start with a harmless example: Set your first secret.

A name and a value

A setting has two parts. Its name, such as DATABASE_URL, tells the program which setting it is. Its value is the connection string, key, or other information supplied by the service.

Discuss the name with your assistant. Enter the value in Keyhole.

Before obtaining a credential, ask which service and credential type the project needs, what it will use it for, and the exact variable name it expects. A database connection string and an account-management API key serve different purposes, even when both come from the same provider.

What Keyhole does

Run Keyhole: Set a Secret in .env… from VS Code's Command Palette. Keyhole asks for the variable's name, checks Git's tracking and ignore rules when VS Code recognizes a repository, and takes the value in a masked input box. It appends the setting to the selected folder's .env. Read any Git message: repository detection has limits.

You start the command yourself. The first release writes to .env only; it does not provide an inbox of requests or write to an assistant's settings file.

.env is an ordinary text file. Your program must be configured to read it. Writing this local file does not update the settings of a deployed service.

Saved, loaded, and accepted are different

  1. Saved: Keyhole wrote the setting to .env and checked the result.
  2. Loaded: the program read that file and received the setting. A program that reads settings at startup needs to restart.
  3. Accepted: the service accepted the credential for the operation you tried.

Keyhole's success message confirms the first step. Check the program's behavior to establish the other two, without printing the value.

Before using a real secret

Follow Keep secrets out of the conversation for the application running your assistant. Keyhole omits the full value from its own messages and logs, but another tool with file access may still read .env. The file is not encrypted.

Git ignore rules help prevent future commits. They do not prevent reads, and they do not remove a secret from an earlier commit.

What you need

  • VS Code desktop 1.134.0 or later.
  • Your project open as a local folder.
  • Git installed and VS Code's built-in Git extension enabled.

Hand checks recorded so far cover macOS with VS Code 1.141.0. Windows and Linux have not been checked.

If a step does not work, start with Troubleshooting. Share the variable's name and the message you saw, without the value or a copy of .env.
