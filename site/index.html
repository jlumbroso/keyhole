API keys & tokens · VS Code

Put the secret
in your project.

Your AI assistant can help you find an API key and explain where it belongs. Enter the value in Keyhole’s masked box: it writes to your project’s .env file and keeps the full value out of its own messages and logs.

First release in preparation. The manual is available now.

From the box to the file.

Run Keyhole: Set a Secret in .env… from VS Code’s Command Palette. Give the setting’s name, then enter its value.

01 /

Checks Git first.

For a repository VS Code recognizes, Keyhole checks that .env is ignored and untracked. It offers to add an ignore rule and checks again. A tracked-file result or reported Git error stops the write. Repository-detection limits.

02 /

Keeps entry masked.

The value appears as dots. You can show it to check what you entered; Keyhole hides it again when you switch to another app.

03 /

Asks before an update.

If the name is already set, Keyhole asks before appending a new value. The old line stays in the file, with a comment identifying which line the new setting supersedes.

04 /

Confirms the destination.

After writing, Keyhole checks the saved value and tells you the setting’s name and file. The confirmation does not print the full value.

Keep the next step out of chat, too

Your assistant can still read files.

Keyhole handles entry into .env. It does not prevent an assistant with file or shell access from opening that file afterward. Configure your assistant’s protections before adding a real credential.

Set up your assistant’s file protections ↗

Ignored does not mean unreadable. Git ignore rules help keep a file out of future commits. They do not remove secrets from past commits or stop programs from opening it.

A marker can identify a value. Keyhole’s log uses a short hash and any recognized public prefix. For values of 32 characters or more, it also includes the last four characters.

Before you start.

A local project, opened as a folder in VS Code.

VS Code desktop

Version 1.134.0 or later, with its built-in Git extension enabled. When VS Code reports no repository, Keyhole permits a write without the repository checks. If you expected a repository, resolve that discrepancy before entering a real value.

Checked on macOS

The command flow has been checked by hand on macOS with VS Code 1.141.0. Windows and Linux have not been tested.

Written locally

Keyhole writes to the selected project’s .env. The extension makes no network requests and opens no listening port.

After saving.

A saved setting does not establish that your app has loaded it or connected to the service. Your app needs a way to read .env, and may need restarting. Hosted services have their own settings; this local write does not configure them.
